## الفكرة

مع مشارك واحد، يكفي مجلد واحد لكل شيء. مع عشرين مشاركاً وخمس مراحل معالجة، يصبح عندك مئة ملف أو أكثر. بعد شهرين لن تتذكر أي ملف نظّفته، ولا بأي إعدادات.

والتخزين يكبر أسرع مما تتوقع. في D4 الملف الخام لكل مشارك حوالي 234 ميجابايت، وفيها 18 مشاركاً: حوالي 4.2 جيجابايت للخام وحده. وإذا حفظت خمس مراحل لكل مشارك، تصل إلى حوالي 21 جيجابايت قبل أي epoch.

فكيف ترتّب مجلداتك وأسماء ملفاتك، وتقرّر مسبقاً ماذا تحفظ؟

## كيف يبدو مجلد مشروع منظّم؟

القفل على `rawdata` يعني أنه للقراءة فقط. كل ما تنتجه المعالجة يذهب إلى `derivatives/eeglab`، بمجلد لكل مشارك.

## كيف أبني المجلدات والأسماء، وأقرّر ما أحفظه؟

**أولاً: الهيكل**

1. أنشئ مجلداً للمشروع، وفيه خمسة مجلدات فقط:
   - `rawdata`: البيانات الخام كما نزّلتها. لا تكتب فيه شيئاً أبداً.
   - `derivatives/eeglab`: كل ما تنتجه المعالجة، بمجلد لكل مشارك.
   - `code`: السكربتات. هي التي تعيد إنتاج كل شيء آخر.
   - `figures`: الرسوم النهائية.
   - `logs`: ملفات الأخطاء التي يكتبها سكربت الدفعات من [الدرس السابق](/lesson/batch-processing/).

هذا نفس منطق BIDS: البيانات الخام في مكان، والمشتقات (<En>derivatives</En>) في مكان آخر، بنفس أسماء المشاركين.

**ثانياً: الأسماء**

2. سمِّ كل ملف من نفس الأجزاء وبنفس الترتيب: المشارك، ثم المهمة، ثم وصف المرحلة، ثم النوع. مثال: `sub-002_task-FaceRecognition_desc-clean_eeg.set`. الجزء `desc-` يقول أي مرحلة هذه، والباقي منسوخ من الملف الخام.
3. اجعل اسم الداتاست داخل EEGLAB يقول نفس الشيء. عند الحفظ من <MenuPath>File > Save current dataset as</MenuPath> اكتب الاسم الكامل، وغيّر <UiLabel>Dataset name</UiLabel> من <MenuPath>Edit > Dataset info</MenuPath> عند الحاجة.

**ثالثاً: التخزين**

4. افتح مجلد `rawdata` في مستكشف الملفات، وانظر إلى حجم ملف `.set` لمشارك واحد. اضربه في عدد المشاركين، ثم في عدد المراحل المستمرة التي تنوي حفظها، لأن كل نسخة مستمرة تحفظها تأخذ تقريباً حجم الملف الخام.
5. قرّر ماذا تحفظ قبل أن تشغّل. قاعدة عملية:
   - **احفظ** ما هو بطيء أو يعتمد على حكمك: أوزان ICA، وقائمة القنوات السيئة، وأرقام المكوّنات التي حذفتها.
   - **أعد حساب** ما هو سريع وآلي: الفلاتر، والمرجع، والتقطيع، والخط القاعدي.
   - **احفظ دائماً** النسخة النهائية التي تدخل الإحصاء.

## كيف أحوّل بياناتي إلى BIDS، أو أشارك ملفاً مع برنامج آخر؟

1. إذا لم تكن بياناتك الخام بصيغة BIDS، فإضافة EEG-BIDS المرفقة مع EEGLAB تحوّلها. افتح <MenuPath>File > BIDS tools > BIDS export wizard (from raw EEG to BIDS)</MenuPath>، واتبع الخطوات: الملفات، ثم المهمة، ثم المشاركين، ثم الأحداث.
2. إذا كانت عندك STUDY جاهزة، فاستخدم <MenuPath>File > BIDS tools > Export STUDY to BIDS folder</MenuPath>.
3. افحص الناتج بـ <MenuPath>File > BIDS tools > Validate BIDS dataset</MenuPath>. يفتح صفحة الفاحص الرسمي في المتصفح.

D4 نفسها مثال على BIDS جاهز: افتح مجلدها وانظر إلى `dataset_description.json` و `README` و `task-FaceRecognition_events.json` ومجلدات `sub-002` وما بعدها.

لمشاركة ملف واحد مع شخص يستخدم برنامجاً آخر، استخدم <MenuPath>File > Export > Data to EDF/BDF/GDF file</MenuPath>. يكتب هذا البند الملف بصيغة قياسية تقرؤها أغلب برامج EEG (يحتاج إضافة Biosig من [درس التثبيت والإضافات](/lesson/install-eeglab/)). استخدمه للمشاركة فقط، وأبقِ داخل مشروعك ملفات `.set` ومجلد BIDS.

## كيف أبني المجلدات وأقدّر التخزين وأصدّر إلى BIDS بسكربت؟

```matlab
[ALLEEG, EEG, CURRENTSET, ALLCOM] = eeglab;
eeglabRoot = fileparts(which('eeglab'));

% Project layout: raw data stay untouched, results go to derivatives
projectRoot = pwd;   % run from inside faces_project
bidsRoot    = fullfile(projectRoot, 'rawdata');            % ds002718 lives here
derivRoot   = fullfile(projectRoot, 'derivatives', 'eeglab');
folders = {bidsRoot, derivRoot, fullfile(projectRoot, 'code'), ...
           fullfile(projectRoot, 'figures'), fullfile(projectRoot, 'logs')};
for k = 1:numel(folders)
    if ~exist(folders{k}, 'dir'), mkdir(folders{k}); end
end

% Storage estimate from the raw files on disk
rawFiles  = dir(fullfile(bidsRoot, 'sub-*', 'eeg', '*_eeg.set'));
rawGB     = sum([rawFiles.bytes]) / 1e9;
nSubjects = numel(rawFiles);
fprintf('%d subject(s) on disk, %.2f GB of raw data\n', nSubjects, rawGB);

% Each continuous stage you save costs about one raw copy per subject
nSavedStages = 2;   % clean continuous + epochs
fprintf('Derivatives for these subjects: up to about %.1f GB\n', rawGB * nSavedStages);
fprintf('Full dataset (18 subjects): about %.1f GB raw\n', 18 * rawGB / max(nSubjects, 1));

% BIDS-style derivative name for one subject and one stage
subj   = 'sub-002';
stage  = 'clean';
outDir = fullfile(derivRoot, subj, 'eeg');
if ~exist(outDir, 'dir'), mkdir(outDir); end
outName = sprintf('%s_task-FaceRecognition_desc-%s_eeg.set', subj, stage);
fprintf('Save stage "%s" as %s\n', stage, fullfile(outDir, outName));

% Small files are cheap: keep ICA weights apart from the data
% icaInfo = struct('icaweights', EEG.icaweights, 'icasphere', EEG.icasphere, ...
%                  'icachansind', EEG.icachansind);
% save(fullfile(outDir, sprintf('%s_task-FaceRecognition_desc-ica.mat', subj)), '-struct', 'icaInfo');

% Convert a non-BIDS dataset (here D1) to BIDS with EEG-BIDS
data = struct('file', {fullfile(eeglabRoot, 'sample_data', 'eeglab_data.set')});
% Practice export only: delete d1_bids when you are done
bids_export(data, 'targetdir', fullfile(projectRoot, 'd1_bids'), ...
    'tInfo', struct('TaskName', 'attention', 'PowerLineFrequency', 60));
```

## أين أضع كل شيء، وبأي صيغة أحفظه؟

| القرار | الاختيار في الدرس | لماذا |
|---|---|---|
| مكان البيانات الخام | `rawdata`، للقراءة فقط | إذا خرّبت ملفاً خاماً بالخطأ، فلا يمكن إصلاحه. كل ما بعده يُعاد من السكربت. |
| مكان النتائج | `derivatives/eeglab/sub-XXX/eeg` | نفس منطق مواصفات BIDS للمشتقات، فيفهمه أي باحث، وتقرؤه أدوات BIDS. |
| عدد المراحل المحفوظة | اثنتان: النسخة النظيفة المستمرة، ثم الـ epochs | تكفي لإعادة أي تحليل لاحق بدون تشغيل ICA من جديد. |
| ما يُحفظ منفصلاً | أوزان ICA، والقنوات السيئة، والمكوّنات المحذوفة | صغيرة جداً، وهي نتيجة ساعات حساب أو قرارات اتخذتها بعينك. |
| ملف أو ملفان لكل داتاست | ملفان، `.set` و `.fdt` (افتراضي EEGLAB 2026.1) | تُحمَّل البيانات أسرع في الـ STUDY. انسخ الملفين أو انقلهما معاً دائماً. وخيار الملف `.set` الواحد موجود في <MenuPath>File > Preferences</MenuPath>. |
| صيغة الأرقام | single (افتراضي EEGLAB) | double يضاعف الحجم بلا فائدة لبيانات EEG. |

## كيف تتأكد أن مشروعك منظّم؟

- مجلد المشروع فيه المجلدات الخمسة، ولم يتغيّر أي ملف في `rawdata` منذ نزّلته.
- السكربت يطبع عدد المشاركين وحجم بياناتهم الخام والتقدير الكلي.
- كل ملف في `derivatives` اسمه يبدأ بـ `sub-` ويحتوي `desc-` باسم مرحلته.
- المجلد `d1_bids` فيه `dataset_description.json` ومجلد `sub-001`.

## أخطاء شائعة في تنظيم الملفات

- **الحفظ فوق الملف الخام.** <MenuPath>File > Resave current dataset(s)</MenuPath> يكتب فوق الملف المفتوح. استخدم دائماً <MenuPath>File > Save current dataset as</MenuPath> مع اسم المرحلة.
- **حفظ كل مرحلة "احتياطاً".** خمس مراحل في 18 مشاركاً تعني أكثر من 20 جيجابايت من D4 وحدها، وأغلبها يُعاد حسابه في دقائق.
- **أسماء مثل `final2_new_REAL.set`.** بعد شهر لا أحد يعرف الفرق. اسم المرحلة في `desc-` يكفي، والإعدادات مكانها السكربت في `code`.
- **فصل السكربت عن النتائج.** نتيجة بلا السكربت الذي أنتجها لا يمكن إعادتها. احفظ السكربت مع كل تشغيل، أو استخدم نظام إدارة نسخ مثل git لمجلد `code`.
