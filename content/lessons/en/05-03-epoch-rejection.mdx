## Why this step matters

ICA removed most blinks, but a few epochs may still have a problem: a sudden movement, an electrode that shifted for a moment, or a large blink that ICA did not fully remove. One epoch with a peak of hundreds of microvolts is enough to distort the whole average.

The simple fix: reject any epoch in which the amplitude crosses a set limit in any channel.

But rejection has a cost. Every epoch you reject is one trial less in the average, and an average of fewer trials is noisier. So the goal is not to reject everything that looks odd, but to reject what actually harms the average.

## The equivalent script

```matlab
% Mark epochs where any channel goes beyond +/-100 uV anywhere in the epoch
EEG = pop_eegthresh(EEG, 1, 1:EEG.nbchan, -100, 100, EEG.xmin, EEG.xmax, 0, 0);
badEpochs = find(EEG.reject.rejthresh);
fprintf('Marked %d of %d epochs\n', numel(badEpochs), EEG.trials);

% Remove the marked epochs
if ~isempty(badEpochs)
    EEG = pop_rejepoch(EEG, EEG.reject.rejthresh, 0);
end
EEG.setname = 'D1 epochs clean';
EEG = eeg_checkset(EEG);
EEG = pop_saveset(EEG, 'filename', 'D1_epochs_clean.set', 'filepath', pwd);

% Add the clean dataset to the EEGLAB window
[ALLEEG, EEG, CURRENTSET] = eeg_store(ALLEEG, EEG);
eeglab redraw
```

The last argument of `pop_eegthresh` is `0`, meaning "mark only, do not reject". The rejection happens on the next lines, so you can print the count first.

## Which value should I choose?

| Setting | Value | Why |
|---|---|---|
| Amplitude threshold after ICA cleaning | ±100 µV | A common starting rule. Brain activity in EEG is usually tens of microvolts, so anything above 100 is most likely an artifact. |
| A strict threshold | ±50 µV or less | Rejects clean epochs because of normal noise and slow waves. Try it in the exercise above. |
| Channels | All channels, including EOG | After ICA the EOG channels are free of blinks, so if a large peak remains there in an epoch, that epoch deserves rejection. |
| Time window | The whole epoch | The simplest choice. You can narrow it to the period where you measure the ERP. |
| Minimum number of trials | No general number | It depends on the size of the ERP component. If more than about a quarter of the trials are rejected, check the data before you raise the threshold. |

**Rule:** the same threshold for every participant and every condition, decided before you see the results. Report the number of rejected epochs per condition in your paper.

## Common mistakes

- **A threshold that is too strict.** It throws away good data, so the average comes from few trials and is noisier. The best threshold is not the smallest possible number.
- **Rejecting before baseline correction.** An epoch shifted away from zero as a whole may cross the limit with no artifact. Correct the baseline first, as in our path.
- **Rejecting instead of using ICA.** If you reject every epoch with a blink without ICA, you may lose a large part of your data, as the interactive demo shows at ±50. ICA fixes blinks; rejection is for rare problems.
- **Very different counts between conditions.** If 40% of one condition and 5% of another are rejected, the comparison is not fair. Check the count for each condition.
- **Forgetting to save after rejection.** In the GUI, rejection creates a new dataset in memory only. Save it before you close EEGLAB.

## How to check it worked

- The command window prints the number marked, such as `1/80 trials marked for rejection`. In D1 after ICA cleaning, expect a small number, about 0 to 3. It varies slightly from run to run because the ICA result varies.
- <UiLabel>Epochs</UiLabel> in the main window equals 80 minus the number rejected.
- `max(abs(EEG.data(:)))` is below 100.
- The file `D1_epochs_clean.set` is in your working folder.
