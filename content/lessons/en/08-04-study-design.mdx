## Why this step matters

The STUDY knows each file's subject, condition and group. But it does not know your question. The design is the question written in EEGLAB's terms: which variables you compare, which of their values, and which participants.

Every plot and every test in the next lessons works on the **current design**. If you pick the wrong design, EEGLAB plots and computes without an error, but for a question that is not yours.

The design also decides the kind of test: do the values come from the same participants (paired) or from different participants (unpaired)? This changes the statistical result a lot.

## Steps in the GUI

**About the data (D6):** the same `animal_mine.study` from the creation lesson. Every participant saw both kinds of picture (animal and distractor), so picture type is **within subjects**. Each participant has one gender (7 women and 7 men), so gender is **between subjects**. Together: a 2×2 mixed design.

**1. Look at the design EEGLAB created**

1. Run the "Starting point" script if the STUDY is not open.
2. Open <MenuPath>Study > Select/Edit study design(s)</MenuPath>. The <UiLabel>Edit STUDY design -- pop_studydesign()</UiLabel> window opens.
3. The <UiLabel>Design name</UiLabel> list holds one design, `STUDY.design 1`. EEGLAB created it by itself when the STUDY was created.
4. The <UiLabel>Edit the independent variables for this design</UiLabel> part has two lines: `Categorical variable: condition - Values (animal - distractor)` and `Categorical variable: group - Values (F - M)`. EEGLAB puts every standard variable with more than one value into the first design.

**2. Create design 2 with a clear name**

1. Press <UiLabel>New</UiLabel> next to the design list. `Design 2` appears with no variables.
2. Press <UiLabel>Rename</UiLabel>, type `image x gender` in <UiLabel>Study design name:</UiLabel>, then <UiLabel>Ok</UiLabel>.
3. In the variables part press <UiLabel>New</UiLabel>. The <UiLabel>Add variable</UiLabel> window opens.
4. In <UiLabel>Select independent variable</UiLabel> choose `condition`. Both values, `animal` and `distractor`, are selected in <UiLabel>Select variable values</UiLabel>. Keep them selected, then <UiLabel>Ok</UiLabel>.
5. Press <UiLabel>New</UiLabel> again, choose `group`, keep `F` and `M` selected, then <UiLabel>Ok</UiLabel>.

**3. Create design 3 with one variable**

1. Press <UiLabel>New</UiLabel> next to the design list, then <UiLabel>Rename</UiLabel> it `image only`.
2. Add one variable only: `condition` with both its values.

**4. Choose the current design and save**

1. Click `image x gender` in the <UiLabel>Design name</UiLabel> list. The design selected when you press <UiLabel>Ok</UiLabel> becomes the current design.
2. Keep <UiLabel>Re-save STUDY file (if saved previously)</UiLabel> ticked, so `animal_mine.study` is saved with its three designs.
3. Press <UiLabel>Ok</UiLabel>. The command window shows `Selecting STUDY design 2`, then `Resaving STUDY`.

<Callout type="note">
**If the STUDY came from BIDS** (the previous lesson), gender is in a field called `gender`, not in `group`. `gender` appears in the same <UiLabel>Select independent variable</UiLabel> list, and works the same way.
</Callout>

## The matching script

```matlab
% STUDY and ALLEEG come from the starting point script
% Design 2: image (within subjects) x gender (between subjects)
STUDY = std_makedesign(STUDY, ALLEEG, 2, 'name', 'image x gender', ...
    'variable1', 'condition', 'values1', {'animal', 'distractor'}, 'vartype1', 'categorical', ...
    'variable2', 'group', 'values2', {'F', 'M'}, 'vartype2', 'categorical');

% Design 3: image only, all participants in one group
STUDY = std_makedesign(STUDY, ALLEEG, 3, 'name', 'image only', ...
    'variable1', 'condition', 'values1', {'animal', 'distractor'}, 'vartype1', 'categorical', ...
    'variable2', 'none');

% Make design 2 the current design and save
STUDY = std_selectdesign(STUDY, ALLEEG, 2);
STUDY = pop_savestudy(STUDY, ALLEEG, 'savemode', 'resave');

% Every design with its variables, values and pairing
for k = 1:numel(STUDY.design)
    d = STUDY.design(k);
    fprintf('Design %d: %s\n', k, d.name);
    for v = 1:numel(d.variable)
        if ~isempty(d.variable(v).label)
            fprintf('   %-10s paired: %-4s values: %s\n', d.variable(v).label, ...
                d.variable(v).pairing, strjoin(d.variable(v).value, ' '));
        end
    end
end
fprintf('Current design: %d\n', STUDY.currentdesign);
eeglab redraw;
```

## Which value should I choose?

**Within subjects or between subjects?**

| | Within subjects | Between subjects |
|---|---|---|
| Meaning | Each participant has every value | Each participant has one value |
| In D6 | Picture type: animal and distractor | Gender: F and M |
| Usually stored in | condition | group |
| Test | paired: compares each participant with themselves, removing differences between people | unpaired: compares two groups of different people |
| Statistical power | Higher for the same number | Lower, and needs more participants |

EEGLAB decides paired or unpaired by itself from the data: if every participant has every value, it is paired. The script prints the decision in the line `paired: on` or `paired: off`.

**Which design for which question?**

| Your question | Design | Why |
|---|---|---|
| Does the ERP differ between animal pictures and the others? | 3, `image only` | A direct paired test on 14 participants, and a plot with two curves instead of four. The 2×2 design also computes the main effect of picture, but it is harder to read. |
| Does the picture effect differ between women and men? | 2, `image x gender` | The interaction between the two variables needs both in one design. |
| Does the ERP differ between women and men? | A design with group only | unpaired, 7 against 7. |

<Callout type="warning">
7 participants per group is a small number for a between-group comparison. We use gender here to learn the mixed design, not to conclude anything about gender. In your own research, set the number of participants before collecting data, based on the effect size you expect.
</Callout>

## Common mistakes

- **Forgetting to choose the current design.** Plots and statistics work on the design selected in the list at the last <UiLabel>Ok</UiLabel>. The script prints `Current design`.
- **Putting a between-subject variable in condition.** If you type gender as a condition, EEGLAB treats it as within subjects. The `paired` line reveals this: gender must be `off`.
- **One design for every question.** The 2×2 design answers the interaction, but the picture effect alone is simpler to read in a one-variable design: two curves instead of four, and a direct paired test.
- **Selecting too few values.** If you select only `animal` in <UiLabel>Select variable values</UiLabel>, there is nothing to compare. Make sure both values are selected.
- **Thinking a new design needs a new precomputation.** Since EEGLAB 2019 trials are saved one by one, and the design selects them at plot time. Do not precompute again because of a new design.
