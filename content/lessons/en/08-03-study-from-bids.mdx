## The idea

In the lesson on creating a STUDY you typed the subject, condition and group by hand. That works with 28 files, but with hundreds it is tiring and error-prone.

Most open data today is in BIDS format, as you saw in [the BIDS and OpenNeuro lesson](/en/lesson/bids-openneuro/): one folder per participant, fixed file names, and a `participants.tsv` table about each participant. The EEG-BIDS plugin reads all of this and builds a STUDY directly.

So how do you build a STUDY from a BIDS folder without typing anything by hand?

## Where do the STUDY fields come from in a BIDS folder?

The participant code comes from the folder name, the session and run from the file name, and the columns of `participants.tsv` (such as gender) become fields in the STUDY.

## What do we download from ds002680, and why only ses-01?

**About the data (raw D6):** the same Go-nogo experiment on OpenNeuro, as ds002680. It has 14 participants (sub-002 to sub-015). Each recording is at 1000 Hz with 31 channels, split into runs of about 3.5 minutes each. Run 1 holds the same categorization task as the ready STUDY: a picture with an animal (`animal_target`) or without one (`animal_distractor`). The ready STUDY files were prepared years ago with EEGLAB 6 and hold 32 channels at 250 Hz, so do not expect their numbers to match the raw data.

**We use session ses-01 only in station 8.** The OpenNeuro copy also has a ses-02 folder, but it is a copy of ses-01: its event files and signal are identical. Do not treat it as a real second session.

We download only two participants, sub-002 (female) and sub-005 (male), and run 1 of ses-01, about 55 MB instead of 4 GB. The goal is to understand the import, and the same method works with all participants.

## How do I import a BIDS folder into a STUDY from the menus?

**1. Download the small part and open the folder**

1. Open "Script to reach this state" under "Starts from" at the top of the lesson, and run it. It downloads four top-level files (`participants.tsv` and others) and seven files per participant, 18 files in all. If a file cannot be downloaded, its name is printed in red and the script continues.
2. Open `participants.tsv` in a text editor. It has two columns: `participant_id` and `gender`. The sub-002 row is F, and the sub-005 row is M.
3. Open `sub-002/ses-01/eeg/sub-002_ses-01_task-gonogo_run-1_events.tsv`. The `trial_type` column holds only `stimulus` or `response`, and the `value` column holds the picture type (`animal_target`, `animal_distractor`) and the answer type (`correct`, `incorrect`).

**2. Import the folder**

1. Open <MenuPath>File > Import data > From BIDS folder structure</MenuPath>. (The same window is also at <MenuPath>File > BIDS tools > Import BIDS folder to STUDY</MenuPath>.)
2. Choose the `ds002680` folder you downloaded. The <UiLabel>Import BIDS data -- pop_importbids()</UiLabel> window opens.
3. In <UiLabel>Enter study name (default is BIDS folder name)</UiLabel> type `gonogo_bids`.
4. Keep <UiLabel>Use BIDS electrode.tsv files (when present) for channel locations; off: look up locations using channel labels</UiLabel> ticked. The channels in this data have non-standard names (such as `CB1`), so a lookup by name cannot find their positions.
5. Keep <UiLabel>Use BIDS event.tsv files for events and use the following BIDS field for event type</UiLabel> ticked, and check that the list next to it is set to `value`.
6. Leave the <UiLabel>Import only the following ...</UiLabel> boxes unticked. We downloaded only two participants, one session and one run.
7. Look at <UiLabel>Study output folder</UiLabel>. Its default is `ds002680/derivatives/eeglab`. Keep it, so the new files are written there and the raw data are not touched.
8. Press <UiLabel>Ok</UiLabel>.

<Callout type="warning">
Red lines appear in the command window, four for each participant we did not download (48 lines for the twelve). EEGLAB tries adding a zero to the name each time: `Folder ... sub-003 does not exist`, then `sub-0003`, then `sub-00003`, and finally `No EEG data folder for subject sub-000003`. This is expected, and your file names are not wrong: `participants.tsv` lists 14 participants and we downloaded two, so EEGLAB skips the others. The script below avoids these lines with the `'subjects'` option.
</Callout>

**3. Read the result**

1. The STUDY appears in the main window. <UiLabel>Nb of subjects</UiLabel> is 2.
2. Open <MenuPath>Study > Edit study info</MenuPath>. The table has two rows: subject is `sub-002` and `sub-005`, session is 1, and run is 1.
3. The gender field does not show in this window, because it shows only the standard fields. The script below prints it from `STUDY.datasetinfo`, and it appears as a variable in the design window, as in [the design lesson](/en/lesson/study-design/).

## How do I import the folder with a script?

```matlab
% bidsFolder comes from the starting point script
[STUDY, ALLEEG] = pop_importbids(bidsFolder, 'subjects', {'sub-002', 'sub-005'}, ...
    'eventtype', 'value', 'bidsevent', 'on', 'bidschanloc', 'on', 'studyName', 'gonogo_bids');
CURRENTSTUDY = 1; EEG = ALLEEG; CURRENTSET = 1:length(EEG);

% Fields from the file names, from participants.tsv and from the data
for k = 1:numel(STUDY.datasetinfo)
    d = STUDY.datasetinfo(k);
    fprintf('%s  session %s  run %s  gender %s  %d Hz  %d channels  %.0f s\n', d.subject, ...
        num2str(d.session), num2str(d.run), d.gender, ALLEEG(k).srate, ALLEEG(k).nbchan, ALLEEG(k).xmax);
end
eeg_eventtypes(ALLEEG(1));
fprintf('STUDY file: %s\n', fullfile(STUDY.filepath, STUDY.filename));
eeglab redraw;
```

## Which import options would I change?

| Option | In this lesson | When to change it |
|---|---|---|
| Event column (`eventtype`) | `value` | Choose the column that separates the conditions. In ds002680 the `trial_type` column only says stimulus or response, so it does not help. Open an events.tsv file first and look. |
| Channel locations (`bidschanloc`) | on | Turn it off only if electrodes.tsv is missing or wrong and the channel names are standard. |
| Participants (`subjects`) | `{'sub-002', 'sub-005'}` | Leave it empty to import everyone. It also accepts row numbers of participants.tsv. |
| Sessions and runs (`sessions`, `runs`) | Not used | To import part of a full set you downloaded. `sessions` takes folder names such as `{'ses-01'}`, not numbers. |
| Output folder (`outputdir`) | The default: `derivatives/eeglab` | Never make it the raw data folder itself. |

## How do I check that the import worked?

- **The main window** shows <UiLabel>Nb of subjects</UiLabel> 2.
- **The script prints two lines:** `sub-002 ... gender F  1000 Hz  31 channels` and `sub-005 ... gender M  1000 Hz  31 channels`.
- **`eeg_eventtypes`** prints the types `animal_target` (50), `animal_distractor` (50), `correct` and `incorrect` for sub-002.
- **The folder** `ds002680/derivatives/eeglab` holds a `gonogo_bids.study` file and two folders, sub-002 and sub-005.

## Can I analyze this STUDY right after the import?

No. Its data are continuous, neither filtered nor epoched, because the import does neither. So a group ERP plotted straight from it means nothing.

Before any group computation, each file needs the same processing and then epoching around the pictures. That is the job of the shared processing script in station 9. So in [the design lesson](/en/lesson/study-design/) we return to `animal_mine.study`, whose files are processed and epoched.

## Common mistakes when importing from BIDS

- **Choosing trial_type instead of value.** Every event becomes `stimulus` or `response`, and the difference between pictures disappears. No error appears, but you will find no condition to compare.
- **Downloading the whole set before trying.** The full ds002680 is 4 GB. Try the import on two participants first, then expand.
- **Using ses-02 as a second session.** In this copy it is a copy of ses-01. If you import it, every participant is doubled with no new information.
- **Editing participants.tsv after importing.** The STUDY copied the values at import time. If you correct the table, import again.
